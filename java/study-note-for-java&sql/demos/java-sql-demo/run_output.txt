Step2_SqlInjection —— SQL 注入攻击演示与防御
================================================================================
========== [危险] 字符串拼接 SQL ==========
SQL: SELECT owner, balance FROM account WHERE owner = '张三'
     查到 → 张三, 余额 1000.0
     共 1 条

SQL: SELECT owner, balance FROM account WHERE owner = '' OR '1'='1'
     查到 → 张三, 余额 1000.0     ← 注意! 攻击字符串让全表数据泄露
     查到 → 李四, 余额 500.0
     共 2 条

SQL: SELECT owner, balance FROM account WHERE owner = '王五'; DROP TABLE account; --'
     共 0 条 (毁灭性语句被拼接进了查询)

========== [安全] PreparedStatement 预编译 ==========
SQL: SELECT owner, balance FROM account WHERE owner = ?   (参数: 张三)
     查到 → 张三, 余额 1000.0
     共 1 条

SQL: SELECT owner, balance FROM account WHERE owner = ?   (参数: ' OR '1'='1)
     共 0 条                     ← 攻击字符串只是普通字符, 无任何破坏力

SQL: SELECT owner, balance FROM account WHERE owner = ?   (参数: 王五'; DROP TABLE account; --)
     共 0 条

Step2 完成 ✓
结论: 攻击字符串在预编译里只是普通的'一串字符', 不具备任何破坏力。

Step3_Transaction —— 银行转账事务
================================================================================
========== 场景1: 正常转账 100 元 ==========
   当前余额: 张三=1000.0  李四=500.0   | 总资产=1500.0
   [事务内] 张三 -100.0
   [事务] 提交成功: 转账完成 ✓
   当前余额: 张三=900.0  李四=600.0   | 总资产=1500.0
观察: 张三-100, 李四+100, 总资产不变 ✓

========== 场景2: 转账到不存在的账户 → 失败并回滚 ==========
   当前余额: 张三=900.0  李四=600.0   | 总资产=1500.0
   [事务内] 张三 -100.0
   [事务] 检测到失败 → 已回滚, 余额保持原样
转账失败: 收款方账户不存在, 转账中止!
   当前余额: 张三=900.0  李四=600.0   | 总资产=1500.0
观察: 张三的扣款被【回滚】, 余额没有变化 ✓

========== 场景3: 对比 —— 没有事务保护会怎样? ==========
   当前余额: 张三=900.0  李四=600.0   | 总资产=1500.0
   [无事务] 张三 -100.0 (已自动提交, 无法撤销)
   [无事务] 此时系统故障... 收款操作未能执行! (钱消失了)
   当前余额: 张三=800.0  李四=600.0   | 总资产=1400.0
观察: 张三的钱扣了, 但没有加到任何人头上 —— 100 元凭空消失 ✗
      这就是【数据不一致】, 事务就是防它的防线。

Step4_BatchPerf —— 批量操作性能对比（1000 条插入）
================================================================================
(a) 逐条执行      : 1000 条, 耗时 5324 ms
(b) 批处理        : 1000 条, 耗时 5045 ms
(c) 批处理+事务   : 1000 条, 耗时    9 ms

最终表中数据量: 1000 条 (三种方式结果相同, 速度天壤之别)
Step4 完成 ✓  提示: 网络数据库(MySQL)上差距会更夸张。

>>> 教学解读: 每次 autocommit 都是一次磁盘同步(fsync), 逐条执行 = 1000 次 fsync;
    事务把 1000 次 fsync 合并成 1 次 → 从 5324ms 降到 9ms (约 600 倍)。
    "批处理 + 事务"是数据导入 / 日志批量写入的工业标配。
